# Day14 Pitfalls

记录本日实际练习中遇到的问题及修正方法。

## 1. unique_ptr 移动方向理解错误

最初使用：

`b = std::move(a);`

但当时 a 是空指针，b 才拥有实际对象。

这会导致 b 原有资源被释放，然后接收 a 的空状态。

修正：根据资源所有权关系确定移动方向。需要把 b 的资源转移给 a 时，应使用 `a = std::move(b);`。

## 2. 移动构造函数错误使用 const T&&

最初写成：

`Student(const Student&& other)`

问题：
- `std::move(other.name)` 得到的是 `const std::string&&`。
- 常规移动构造和移动赋值不能接收 const 右值引用。
- 因此成员可能退化为拷贝操作。

修正：

`Student(Student&& other) noexcept`

## 3. Lambda 遍历时不必要的对象复制

最初使用：

`[](Student x)`

这会按值传递 Student，调用时产生对象复制。

修正：
- 只读访问使用 `const Student&`。
- 需要修改原对象时使用 `Student&`。

## 4. 条件判断边界错误

成绩筛选和及格统计中，最初使用 `>`。

但题目要求的是大于等于，因此应使用 `>=`。

例如：
- 90 分应满足大于等于 90。
- 60 分应计入及格人数。

## 5. Lambda 捕获方式与任务要求不一致

成绩修改任务要求引用捕获，但最初使用 `[threshold]`。

修正为 `[&threshold]`，让 Lambda 访问外部阈值变量。

注意：修改学生成绩是通过 `Student& x` 实现的，不是通过捕获列表实现的。

## 6. mutable 理解不足

最初不清楚为什么值捕获需要 mutable。

核心原因：
- Lambda 默认的调用运算符是 const 成员函数。
- 值捕获的成员默认不能在函数体内修改。
- mutable 允许修改 Lambda 内部保存的值捕获副本。
- mutable 不会使外部变量发生改变。

## 7. 引用捕获生命周期理解不准确

最初将问题理解为捕获对象为空会导致异常。

实际问题是：如果被引用的外部变量已经销毁，Lambda 仍然访问该引用，就会产生未定义行为。

引用捕获不会延长变量生命周期。
